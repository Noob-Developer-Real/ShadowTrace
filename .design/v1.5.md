# ShadowTrace 1.5 · Protected transfers

The requested order is scheduled exports and cloud links, followed by sensitive transfer approval and cumulative limits. The workflow uses the approved workspace, static evidence, and inline feedback.

| Journey | Entry and controls | Saved outcome and recovery |
|---|---|---|
| ST15-01 Scheduled export | Source operator configures a scheduled task and immutable nominal UTC occurrence ID. Run the supplied CSV runner with schedule alias, nominal timestamp, actor alias, approved destination alias, input and private output paths. | A deterministic UUID identifies the occurrence across retries and credential rotation. The runner validates and hashes staged data, asks ShadowTrace before writing, and atomically creates the delivery file. Protection history shows the schedule alias and nominal time. Pending approval waits for the same occurrence and identical bytes. Denials and unavailable checks leave the output untouched. The source scheduler owns cadence, retry, alerting and source data. |
| ST15-02 Managed cloud link | Trusted source stages a private versioned object under the prescribed prefix, submits a share intent with the exact recipient and TTL, then registers the matching allowed operation. Protection → Managed transfers lists links and allows workspace admins to revoke. The invited member signs in to download. | ShadowTrace serves the pinned object version through the protected download route and verifies the authorized digest. The workspace and recipient are checked before fetching and again before releasing. A revoked or expired link, another member, inaccessible storage, a changed object or an incorrect digest leaves the download unavailable. The demo uses a storage adapter with synthetic bytes. |
| ST15-03 Approvals | In Protection, admins set the customer approval threshold. Connected sources can explicitly flag a transfer as sensitive. Protection → Managed transfers shows pending requests, their action, count, destination, source and deadline. An eligible admin approves or denies. | Requests are bound to the exact intent and policy revision for 24 hours. An identified requester cannot approve their own transfer. Machine schedules can have independent human approval. The source retries the same request only after review, and ShadowTrace rechecks policy and budget before allowing once. Changed bytes, metadata, source credential, policy or expiry require a fresh review. |
| ST15-04 Cumulative limit | Protection → 24-hour actor limit. An integer controls the total authorized rows across exports, downloads and shares, sources and destinations for the same stable actor alias. | Successful decisions reserve rows in a PostgreSQL transaction serialized per workspace and actor. A blocked or pending transfer reserves nothing. The next request over the limit is denied even if it meets its per-action limit. The history shows a cumulative-denial reason. |

| Field | Type, constraints and use |
|---|---|
| Policy cumulative_limit and approval_threshold | Optional nonnegative integers in policy save. 0 disables that rule. Existing revisions retain their settings if a legacy client omits these fields. Cumulative max 10,000,000 and threshold max 1,000,000. Customer approval applies at or above the threshold. |
| Transfer channel | interactive by default, scheduled for export or cloud_link for share. Persisted with decision. |
| schedule_id and scheduled_for | ASCII ID and UTC timestamp, required together for scheduled exports. Nominal time comes from the source scheduler. |
| sensitive and requester_id | Boolean default false and optional workspace principal UUID. Interactive and cloud approval require an identified requester. Connector must bind this to the authenticated user. |
| recipient_id and link_minutes | Workspace principal UUID and integer 1–1440, required for cloud links. Bind these to the requested transfer. |
| Link version | Opaque S3 object version ID from the private staging upload. Reject null/unversioned values. Link ID is the operation UUID. Use the fixed workspace/object prefix. |
| Review action | Approve or Deny, admin only, CSRF checked. No note required to make a decision, both decisions audited. |
| Cloud lifecycle | Active, expired, revoked derived from server timestamps. A revocation only prevents new delivery. An already downloaded copy may remain with its recipient. |

Acceptance: duplicate scheduler trigger delivers at most once, approved cloud object reaches only its recipient and can be revoked, policy and audience changes invalidate applicable requests, races cannot bypass rolling limits, prior keys and decisions still work, and real screens work on desktop and mobile. Live AWS testing requires a configured private bucket. No account access or cloud deployment is part of the local upgrade.
