# ShadowTrace 1.1 design changes

The user asked to implement all four discussed additions, keep the approved light workspace with static evidence and inline feedback, and deliver the completed product. The user previously waived a separate design phase for this build. This addendum covers the affected journeys in the approved v0.1 workspace.

| Flow | Entry and controls | Authority and data | Outcome and recovery |
|---|---|---|---|
| FLW-06 · Live synthetic demo | SCR-03 Overview, above metrics. Run normal activity, Run suspicious export, Open activity, and when created, Open generated case. | Demo profile and loopback only. An active member of the named workspace submits an enumerated scenario and a generated UUID and timestamp. The server resolves the local seeded key for that workspace. Live events pass through the normal authenticated ingest API. Synthetic baseline history is separately seeded with historical receipt timestamps. | Shows accepted/replayed counts and the scoped result. Pending disables both buttons. Interrupted responses allow retrying the same run. Reload reads committed data. Missing or revoked seed key gives actionable feedback. |
| FLW-07 · Actor context | SCR-05 case findings show comparison. Actor ID links to SCR-09 actor profile, also reachable from Activity. Profile shows activity totals, latest events, case links and the baseline for each resource. | Current workspace and exact pseudonymous ID. Successful views in nonempty five-minute UTC buckets over the preceding 14 days. Require 8 buckets spanning 3 UTC dates. Case calculation excludes the five minutes before the case opened, as well as later data. | Display median, 90th percentile, sample size, and case comparison when enough data is retained. Distinguish sparse history, unavailable actor, and expired evidence. Baseline is context for investigation. |
| FLW-08 · Source health | SCR-07 Integration, below request example and before key controls. Each key shows latest accepted event, volume, replays, rejections, throttles and active/revoked state. | Admin only. Authenticated deliveries attributed to the scoped key. Record accepted/replayed in the ingest transaction and categorized refusals separately. Aggregate by UTC day and retain on workspace schedule. | Zero since UTC midnight, no activity yet, and quiet for 24h are distinct. Unattributable invalid-key traffic is omitted. Older installations may show latest receipt before these counters have data. |
| FLW-04 · Case ownership | SCR-05 Review, before review status. Owner selector and Save owner, close reason plus existing note. SCR-04 shows current owner with a My cases filter. SCR-05 also offers evidence download. | Analysts and admins in the requested workspace. Case row lock and revision for owner/review edits. Case owner restricted by a composite membership foreign key. Review disposition is persisted with the review. Download includes case snapshot, signals, evidence and defined limits, with a canonical SHA-256 checksum and an audit record. | Inline pending, success, validation and conflict feedback. Reload preserves review draft. A repeated owner save to the same owner is safe. Member removal clears ownership. Evidence expires with retention. Bundle omission limits are explicit. |
| FLW-09 · Historical rule replay | SCR-07 Rules. Edit existing controls, Preview impact, examine current/proposed counts and changed examples, then optionally save. | Admin only and CSRF protected. Read up to 5,000 successful events covering at most 24 hours, plus possible window warm-up. Rules are evaluated by receipt time. Truncated runs report the period actually evaluated. Existing rules and cases receive no writes. | Clearly label matched events and no-data cases. Rejection or delay leaves thresholds in place. Changes to thresholds clear stale results. Save uses the existing revision check. |

| New field ID | Contract |
|---|---|
| FLD-demo-scenario | Button, required; normal or incident; server validates. |
| FLD-demo-run | Generated UUID and RFC 3339 timestamp; hidden client values; timestamp within the demo retry window; event IDs and payloads stable across retries. |
| FLD-actor-profile | Exact ID path parameter, same format and bounds as event actor ID; scope comes from authenticated workspace; inaccessible and missing use standard unavailable page. |
| FLD-case-owner | Optional select; current assignee default or Unassigned; server validates against active workspace membership and expected case revision; saved to case. |
| FLD-close-reason | Select; no initial value; Approved activity, Policy violation, False positive or Other; required by the new browser form for closed cases; old API clients can omit; stored on review. |
| FLD-owner-filter | Optional My cases checkbox; off initially; query string and cursor scope; server derives actor from current principal. |
| FLD-preview-thresholds | Same view/export inputs and validation as Rules; admin only; preview does not persist the numbers or create cases. |

The live demo, source health, case ownership, actor profile and rule replay reuse the existing panel, table, input, badge, and inline status components. Keyboard controls use native links, buttons and selects. Responsive panels stack at existing breakpoints. Missing membership and foreign links return the generic unavailable screen. New UI uses the existing palette, both themes, and static presentation.

Acceptance checks include synthetic demo retry and production denial, tenant-scoped actor/health/replay/evidence access, sparse historical context, cross-workspace owner denial, membership removal, disposition history, and verification of the downloaded bundle against a modified copy. Verify at desktop and 320px, keyboard focus, and automated accessibility. No live customer identity, traffic, market measurements, or production evidence is assumed.
